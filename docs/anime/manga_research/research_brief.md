# 漫画データベース調査ブリーフ（全エージェント共通）

## 目的
千葉県成田市の格闘技ジム「FLAT UP GYM」が、オリジナルの漫画・アニメを作るための研究データベースです。
ヤンキー・不良漫画と、格闘技・武道漫画の「演出・心理描写・言葉のテンポ・ギャグの作り方」を研究し、著作権に配慮したうえでオリジナル作品に活かします。
作品の思想：「不良漫画は好き。でも不良は嫌い。」「強さとは優しさであり、かっこよさである。」「世界一、初心者に優しい格闘技ジム。」

## やること
1. 担当リストの各作品について、WebSearch / WebFetch で事実（正式タイトル・作者・出版社・掲載誌・連載期間・巻数・続編や外伝）を確認する。
2. 確認できた情報源のURLを記録する。優先順位：出版社・公式サイト → 書誌情報（国立国会図書館、出版社の書籍ページ）→ Wikipedia などの二次情報。
3. 分析の項目（テーマ・心理描写・セリフの特徴・演出・ギャグ）は、自分の言葉で書く。
4. 担当リストに「外伝・スピンオフを全部」とある場合は、公式の外伝・続編を漏れなく調べ、1作品＝1行として追加する。
5. 「追加で○作」とある場合は、代表的で知名度の高い作品を選んで追加する。

## 著作権の厳守（とても大事）
- 原作のセリフ・名ゼリフ・モノローグを**引用しない**。dialogue_style には「語尾を伸ばす」「当て字のルビを多用」のように**特徴だけ**を書く。
- コマの構図を細かく再現した描写を書かない。
- flatup_use には、その作品から学べる演出の**一般的な技法**と、FLATUP向けの**オリジナルの**アイデア（短いセリフ案はオリジナルの言葉で）を書く。
- copyright_caution には、FLATUP作品で真似してはいけない要素（キャラの外見、固有の衣装、特徴的な決めゼリフ、ロゴ、チーム名など）を具体的に書く。

## 正確さ
- 推測で事実を埋めない。確認できない項目は「未確認」と書く。
- net_reputation（ネット・SNSでの評判）は、各主張の頭に [事実] [感想] [推測] のどれかを付ける。X（旧Twitter）を直接検索できない場合、Webで拾える評判だけでよい。その場合は「X直接検索なし」と明記する。
- status は次の3つから選ぶ：
  - 「確認済み」：出版社・公式・書誌のURLで基本情報を確認した
  - 「二次情報で確認」：Wikipedia などの二次情報だけで確認した
  - 「未確認」：基本情報を確認できなかった

## 出力
担当ファイル（プロンプトで指定）に、**JSONの配列**を Write ツールで保存する（UTF-8）。1作品＝1オブジェクトで、キーは下のとおり。値はすべて文字列にする。ただし sources だけはURLの配列。

```json
{
  "title": "正式タイトル",
  "title_kana": "よみがな",
  "category": "ヤンキー・不良 | 格闘技・武道 | 両方",
  "series_group": "シリーズ名（例：刃牙シリーズ／クローズ・WORSTシリーズ／単独）",
  "relation": "本編 | 続編 | 外伝 | スピンオフ | 前日譚 | 関連作品",
  "author_story": "原作者（いなければ作者）",
  "author_art": "作画（原作者と同じなら同じ名前）",
  "publisher": "出版社",
  "magazine": "掲載誌・掲載媒体",
  "run_period": "連載期間（例：1991–1997）",
  "volumes": "単行本の巻数（版の種類が分かれば併記）",
  "genre_tags": "不良／格闘技／ボクシング／学園／ギャグ／教育 など",
  "related_works": "続編・外伝・同じ作者の関連作",
  "themes": "主なテーマ（友情、矜持、勇気、優しさ…）",
  "psychology": "心理描写の特徴（恐怖・不安・葛藤・成長の描き方）",
  "dialogue_style": "セリフの特徴（テンポ・語調。引用はしない）",
  "direction_style": "演出の特徴（構図・表情・集中線・間・黒ベタ）",
  "gag_style": "ギャグの特徴（誇張・勘違い・落差）",
  "flatup_use": "FLATUPでの活用案（技法と、オリジナルのアイデア）",
  "copyright_caution": "真似してはいけない要素",
  "net_reputation": "[事実]… [感想]… [推測]…",
  "sources": ["https://..."],
  "checked_date": "2026-10-29",
  "status": "確認済み | 二次情報で確認 | 未確認"
}
```

最後の返答は短くまとめる：保存した件数、status ごとの件数、確認しきれなかった点。JSONの中身は返答に貼らない。
